# ecommerce-cro-auditor

**סקיל ל-Claude שמבצע ביקורת המרות (CRO) מלאה ושיטתית לחנות אונליין, בעברית, ומחזיר רשימת שינויים מדורגת שאפשר לבצע.**

## המטרה

רוב בעלי החנויות יודעים שיש להם בעיה ("אנשים נכנסים ולא קונים") ולא יודעים איפה. ביקורת CRO מקצועית עולה אלפי שקלים, לוקחת שבועות, ובסוף מגיע מסמך כללי. הסקיל הזה נותן ל-Claude תהליך קבוע של יועץ CRO מנוסה, ומפעיל אותו על החנות שלך:

- הוא **בודק את כל האתר**, עמוד-עמוד, במובייל ובדסקטופ, ולא רק את דף הבית.
- הוא **מסתכל מששה כיוונים שונים** (CRO, UX, פסיכולוגיה צרכנית, מובייל, נגישות וביצועים, וסנגור שטן שמערער על כולם), במקום דעה אחת.
- הוא **מפריד בין מה שידוע למה שמנחשים**: כל שינוי מסווג כעובדה מבוססת, השערה, או ניסוי A/B.
- הוא **מדרג כל שינוי** לפי השפעה, ביטחון ומאמץ, כדי שתדע מה לעשות קודם.
- הוא **לא נוגע בקוד** עד שאתה מאשר במפורש אילו שינויים לבצע.

התוצר הסופי הוא דוח בעברית עם רשימת שינויים לפי אזור באתר (דף הבית, קטגוריה, מוצר, עגלה, צ'קאאוט...), כשלכל שינוי כתוב מה בדיוק לשנות, למה, כמה זה שווה, ואיך נדע שזה עבד.

## למי זה מיועד

- בעלי חנויות אונליין (Shopify, WooCommerce, Wix, Magento, פלטפורמות ישראליות או אתר מותאם) שרוצים לדעת מה מוריד להם את ההמרה.
- מעצבים, מפתחים ואנשי שיווק שעושים ביקורת ללקוח ורוצים תהליך מסודר ומתועד.
- מי שכבר משתמש ב-Claude ורוצה שהוא יעבוד כמו צוות CRO ולא כמו צ'אט.

לא צריך לדעת לתכנת. צריך את הכתובת של החנות, ואם יש, קצת נתונים (שיעור המרה, אחוז תנועה ממובייל).

## איך משתמשים

### 1. מתקינים (פעם אחת)

**Claude Code**, הדרך הכי פשוטה, שתי שורות:

```
/plugin marketplace add galsolomon/ecommerce-cro-auditor
/plugin install ecommerce-cro-auditor@galsolomon-skills
```

**Claude Code**, העתקה ידנית:

```bash
git clone https://github.com/galsolomon/ecommerce-cro-auditor.git
mkdir -p ~/.claude/skills
cp -r ecommerce-cro-auditor/skills/ecommerce-cro-auditor ~/.claude/skills/
```

**Claude.ai** (האתר או האפליקציה): להוריד את הקובץ [`dist/ecommerce-cro-auditor.skill`](dist/ecommerce-cro-auditor.skill) ולהעלות אותו בהגדרות, תחת Skills. ב-Claude.ai אין סוכנים מקבילים, ולכן ששת התפקידים רצים בזה אחר זה; הסקיל יודע את זה ומציין זאת בדוח.

**דרישות**: Python 3.8 ומעלה. לצילומי מסך: `pip install playwright` ואז `playwright install chromium`. בלי Playwright הסקיל עובד במצב `--no-browser`, בלי צילומי מסך.

### 2. כותבים ל-Claude מה רוצים

לא צריך ניסוח מיוחד. למשל:

> תעשה ביקורת CRO מלאה לחנות שלי: https://example.co.il. זו חנות Shopify לבגדי ילדים, רוב התנועה מהמובייל, שיעור ההמרה בערך 1.2%.

או פשוט:

> למה אנשים נכנסים לאתר שלי ולא קונים? https://example.co.il

### 3. מה קורה אחר כך

Claude טוען את הסקיל ופותח תיקייה בשם `cro-audit/`. משם הוא עובר על תשעה שלבים:

| שלב | מה קורה | כמה זמן (בערך) |
|---|---|---|
| 0 | שואל אותך כמה שאלות (מטרה, קהל, פלטפורמה), וסורק את האתר: עד 25 עמודים, צילומי מסך במובייל ובדסקטופ | 5 דקות |
| 1 | חוקר מקורות מקצועיים (Baymard, Nielsen Norman Group, WCAG, web.dev) ובנצ'מרקים לענף שלך | 10 דקות |
| 2 | כותב חמישה מסמכי ידע מותאמים לחנות: CRO, UX, פסיכולוגיה, מובייל, כלים | 10 דקות |
| 3 | מפעיל שישה סוכני AI, כל אחד בתפקיד אחר, שסורקים את האתר ומחזירים ממצאים | 20 עד 40 דקות |
| 4 | מאחד את הממצאים, מזהה כפילויות וסתירות, ומכריע | 10 דקות |
| 5 | עובר שוב על כל עמוד, במובייל ובדסקטופ, ומאמת כל ממצא מול צילום המסך | 30 עד 60 דקות |
| 6 עד 8 | מייצר את הדוח: רשימת שינויים לפי אזור, דירוג, סיווג, וכרטיס ניסוי לכל A/B | 10 דקות |
| 9 | **עוצר ושואל אותך** אילו שינויים לבצע. רק אחרי אישור מפורש הוא נוגע בקוד | לפי ההחלטה שלך |

בסוף שלב 8 תקבל תקציר מנהלים ואת עשרת השינויים הראשונים בצ'אט, והדוח המלא ב-`cro-audit/08-final-report.md`. אפשר לפתוח אותו בכל עורך טקסט או להעלות אותו ל-Claude ולבקש הסברים.

### הפעלה של חלקים בנפרד

```bash
# סריקה בלבד (צילומי מסך ואותות טכניים)
python ~/.claude/skills/ecommerce-cro-auditor/scripts/crawl_site.py https://example.co.il --out cro-audit/02-crawl --try-checkout

# איחוד ממצאים של סוכנים שכבר רצו
python ~/.claude/skills/ecommerce-cro-auditor/scripts/merge_findings.py cro-audit/05-agents --out cro-audit/06-merged

# בניית שלד הדוח
python ~/.claude/skills/ecommerce-cro-auditor/scripts/build_report.py --audit cro-audit
```

לכל סקריפט יש `--help` בעברית.

## ששת הסוכנים

שישה סוכנים שמקבלים אותה הנחיה מחזירים שש גרסאות של אותה רשימה. לכן לכל סוכן יש תפקיד, זווית מבט, רשימת בדיקה משלו, ורשימה מפורשת של מה *לא* לבדוק:

| סוכן | מה הוא מכסה |
|---|---|
| **מומחה CRO** | המשפך: הצעת ערך, קריאות לפעולה, מחיר ומשלוח, עגלה, צ'קאאוט, אמון |
| **חוקר UX** | ניווט, חיפוש, פילטרים, טפסים, משוב, שגיאות, עקביות, RTL |
| **פסיכולוג צרכני** | הוכחה חברתית, מחסור, עיגון, עומס בחירה, ניסוח, דפוסים אפלים |
| **מומחה מובייל** | אזור האגודל, מקלדת, גלילה, כפתור דביק, תשלום מהיר, ביצועים במובייל |
| **מומחה נגישות וביצועים** | WCAG 2.2, ניגודיות, מקלדת, Core Web Vitals, משקל עמוד |
| **Devil's Advocate** | לא מחפש בעיות באתר, אלא חורים בממצאים של החמישה: ראיות חלשות, סיכונים, סתירות, נקודות עיוורות |

## דוגמה לפלט

בתיקייה [`examples/demo-store/`](examples/demo-store/) יש פלט אמיתי של הסקיל על חנות דמה קטנה עם בעיות מכוונות: סיכום הסריקה, צילומי מסך, הסטטיסטיקה של ששת הסוכנים (125 ממצאים, 66 ערעורים), קובץ הסתירות וההכרעות, והדוח הסופי עם 106 שינויים לפי אזור. זו הדרך המהירה ביותר להבין מה מקבלים בסוף.

## עקרונות

1. **תפקידים שונים, לא שש דעות דומות.** לכל סוכן יש מה לבדוק ומה לא, וה-Devil's Advocate בודק את הסוכנים ולא את האתר.
2. **תצפית ומקור לפני דעה.** ממצא בלי צילום מסך או מדד הוא ניחוש; ממצא בלי מקור הוא טעם אישי. שניהם נכנסים לדוח רק כהשערה.
3. **המלצה לפני יישום.** הסקיל מסתיים ברשימה מאושרת, לא בקוד. שינוי בחנות פעילה בלי אישור הוא סיכון עסקי.
4. **בלי דפוסים אפלים.** טיימרים מזויפים, מלאי מזויף, הרשמה מסומנת מראש: הסקיל מסמן אותם כממצא שלילי, לא כהמלצה.
5. **הכל בעברית ברורה.** מונחים שמקובלים באנגלית (CRO, CTA, Checkout, A/B) נשארים באנגלית עם הסבר בפעם הראשונה.

## שאלות נפוצות

**הסקיל משנה את האתר שלי?** לא, עד שמאשרים במפורש אילו פריטים לבצע (שלב 9). כל השלבים הקודמים קוראים בלבד.

**כמה זמן זה לוקח?** תלוי בגודל החנות ובסביבה. ב-Claude Code עם סוכנים מקבילים, ביקורת מלאה של 25 עמודים אורכת בדרך כלל בין שעה לשלוש שעות של עבודת Claude. ב-Claude.ai בלי סוכנים מקבילים, יותר.

**זה עובד על חנות שלא בעברית?** כן. התוצרים בעברית, ציטוטים מהאתר בשפת המקור. מסמך השוק הישראלי נטען רק אם החנות ישראלית.

**זה מחליף ניסויי A/B?** לא. הסקיל מפריד בין מה שידוע (עובדה), מה שסביר (השערה) ומה שצריך לבדוק (ניסוי), ובונה כרטיס ניסוי לכל פריט מהסוג השלישי. הוא גם אומר בכנות מתי לחנות אין מספיק תנועה לניסוי.

**המספרים במסמכי הידע מדויקים?** הם נקודת פתיחה ממחקרים ידועים (Baymard, Nielsen Norman Group, W3C, web.dev), ושלב 1 בתהליך נועד לאמת אותם מחדש בכל ביקורת. אם אין גישה לאינטרנט, הסקיל כותב זאת במפורש.

**מותר לי להשתמש בזה בעבודה עם לקוחות?** כן. ראה הרישיון למטה.
